# AGENTS.md

## Project Overview

**Abandoned, Not Forgotten: Voices on the Moon** is an interactive 3D lunar museum and guided story tour built for the 2026 NASA International Space Apps Challenge. Visitors fly across a 16K quadtree-tiled 3D Moon with **Lo-Ro** (an animated orbital guide inspired by NASA's Lunar Reconnaissance Orbiter) to explore **29 verified lunar hardware sites** (9 Hero Sites + 20 Secondary Sites), listen to first-person equipment memory logs, compare 1960s/1970s surface photos with modern LROC orbital imagery, and run interactive science simulations.

## What to Do After Cloning the Repo

### 1. Fast Start (Ready Out of the Box)
Pre-built WebP texture pyramids (`L0`–`L3`), the LOLA `.u16` elevation grid, `.glb` spacecraft models, site imagery, and narration `.mp3` files are already committed under `public/`.

```bash
# 1. Install dependencies (uses Bun + bun.lock)
bun install

# 2. Verify dataset integrity, types, and unit tests
bun run check
bun test

# 3. Start the local Vite dev server
bun run dev
```

### 2. Optional: Regenerating Raw NASA Assets & `stars_8k.webp`
Multi-hundred-MB raw NASA SVS source TIFFs (`raw/`) and the oversized 8K celestial map (`public/textures/sky/stars_8k.webp`) are gitignored to keep the repository lightweight (the app automatically falls back to the committed `stars_4k.webp` when `stars_8k.webp` is absent).

If you want to generate `public/textures/sky/stars_8k.webp` or rebuild any asset pipeline output from scratch:

```bash
# Download raw NASA SVS #4720 Moon Kit & #3895 Star Map into raw/moon-kit/
# (Use `bun scripts/fetch-moon-kit.mjs --level=p0` to skip the multi-hundred-MB 8K/16K TIFFs)
bun run assets:fetch

# Build L0–L3 Moon color/normal WebP tiles, height_1440x720.u16, and stars_8k.webp
bun run assets:textures

# Optional: re-fetch/build site Then/Now WebP images, .glb models, or TTS narration (requires edge-tts + ffmpeg)
bun run assets:site-media
bun run assets:models
bun run assets:narration
```

## Build, Test & Verification Commands

All package management, typechecking, linting, formatting, and tests run via **Bun**, while Vite and Wrangler execute via Node in `package.json` scripts:

| Command | Description |
| :--- | :--- |
| `bun install` | Install dependencies from `bun.lock` |
| `bun run dev` | Start local Vite dev server (`node ./node_modules/vite/bin/vite.js`) |
| `bun run build` | Run TypeScript typecheck (`bun check`) and build production bundle to `dist/` |
| `bun run preview` | Build and preview locally via Cloudflare Wrangler (`wrangler dev`) |
| `bun run deploy` | Build and deploy to Cloudflare Workers/Pages (`wrangler deploy`) |
| `bun test` | Run all unit and dataset validation tests (`geo`, `heightSampler`, `tourEngine`, `data`) |
| `bun run content:check` | Validate all site coordinates, schemas, asset paths, and citations (`bun test src/data`) |
| `bun run check` | Run TypeScript compiler validation |
| `bun run lint` | Run Bun linter (`bun lint`) |
| `bun run format` | Format codebase (`bun fmt`) |

> **Before finishing any task or PR:** Ensure `bun run lint && bun run check && bun test && bun run build` all pass cleanly.

## How Things Work (Architecture & Conventions)

### 1. Two-Layer App Shell (`src/App.tsx`)
The UI is split into two strictly decoupled layers stacked inside a full-viewport container:
- **`src/scene/` (3D WebGL Layer):** Rendered inside `@react-three/fiber`'s `<Canvas>`, wrapped in `SceneErrorBoundary` with a 2D SVG map fallback (`Fallback2DMoonMap`) if WebGL context is lost.
- **`src/hud/` (DOM Overlay Layer):** Rendered above the canvas (`pointer-events-none` root with interactive child panels) for Lo-Ro dialogue, the 5-chapter Guided Tour bar, Free Explore filters, the Site Story Drawer, Then/Now comparison sliders, and interactive science widgets.

**Strict Boundary Rule:** `src/scene/` must **never** import from `src/hud/`, and `src/hud/` must **never** import from `src/scene/`. They communicate exclusively through:
1. **`src/store/useAppStore.ts`:** Zustand state store (app mode `intro | tour | explore`, `selectedSiteId`, `hoveredSiteId`, `activeStoryTab`, `dialogue`, `loroMood`, `sunLongitude`/`sunLatitude`, and persisted user `settings`).
2. **`src/engine/camera.ts` (`cameraBus`):** Command bus connecting HUD/tour events (`flyToLatLon`, `flyOverview`, `flyEarthrise`, `goHome`, `zoomIn`, `zoomOut`, `rotateBy`) to the R3F `CameraRig` (`src/scene/CameraRig.tsx`).

### 2. 3D Moon Globe & Progressive Quadtree Tile Streaming (`src/scene/moon/`)
- **32-Patch Spherical Grid:** The Moon is divided into `8 cols × 4 rows` (45° × 45° spherical patches) generated by `createTileGeometry.ts` and rendered by `MoonGlobe.tsx` / `MoonTile.tsx`.
- **LOLA Vertex Displacement:** `heightSampler.ts` loads `/textures/moon/height_1440x720.u16` (16-bit LOLA laser altimetry DEM) to displace vertices and position surface markers accurately on lunar terrain.
- **LOD Tile Manager (`tileManager.ts`):** `moonTileManager` boots immediately with `L0` (128px) and `L1` (512px) tiles, evaluates camera distance and frustum visibility every 150 ms to stream `L2` (1024px) and `L3` (2048px color / 1440px normal) tiles on demand, pre-warms `L3` tiles via `preloadSite(lat, lon)` when camera flight starts, and evicts unused high-res tiles according to GPU quality budgets (`src/lib/quality.ts`).
- **Lunar Photometry Shader:** `MoonTile.tsx` injects custom Lommel-Seeliger + Hapke retroreflective regolith shading into `MeshStandardMaterial.onBeforeCompile`.

### 3. Coordinate & Scale Conventions (`src/lib/geo.ts`, `src/lib/constants.ts`)
- **Latitude:** `−90°` (South Pole) to `+90°` (North Pole).
- **Longitude:** **East-positive**, `−180°` to `+180°`.
- **Scene Scale:** Mean lunar radius `MOON_RADIUS_KM = 1737.4` equals **`1.0` scene unit** (`HEIGHT_EXAGGERATION = 3`).
- **Axes:** Sub-Earth point `(0°N, 0°E)` faces **`+X`**, North Pole is **`+Y`**, and East longitudes extend toward **`−Z`** (so East is to the right when viewing the nearside from `+X`). Always use `latLonToVector3()` and `vector3ToLatLon()` from `@/lib/geo`.

### 4. Data-Driven Content & Citations (`src/data/`)
- All site metadata, coordinates, narratives, and tour sequences live in `src/data/` (`heroSites.ts`, `secondarySites.ts`, `tourChapters.ts`, `sources.ts`) and are validated against strict Zod schemas in `src/data/schema.ts`.
- Every site, stat, image, and dialogue line must reference valid IDs in `SOURCES` (`src/data/sources.ts`), which `src/data/data.test.ts` enforces alongside file-existence checks in `public/`.

### 5. Guided Tour Engine & Audio (`src/engine/`, `src/audio/`)
- **`tourEngine.ts`:** Pure deterministic state reducer (`tourReducer`) handling chapter/beat progression (`flySite`, `narrate`, `openTab`, `spotlightWidget`, `overview`). `useTourRunner.ts` executes camera flights, dialogue reveals, and voice playback for the active beat.
- **`AudioEngine.ts` & `speech.ts`:** Synthesizes ambient lunar drone, UI clicks, and authentic Apollo Quindar tones (`2525 Hz` intro / `2475 Hz` outro) via Web Audio API, and plays pre-generated neural narration clips (`/audio/narration/<lineId>.mp3`) with automatic Web Speech API fallback.

### 6. Build & Bundler Notes (`vite.config.ts`)
- Path alias `@/` maps to `./src/`.
- `optimizeBarrels()` in `vite.config.ts` rewrites barrel imports from `lucide-react`, `@react-three/drei`, and `three-stdlib` directly to their underlying submodules so Vite only transforms used modules.
- Manual chunking splits `three`, `@react-three/*` (`r3f`), and `motion` into dedicated vendor bundles.
